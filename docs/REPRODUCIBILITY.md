# Reproducibility

All repository tests, catalog inspection, preflight, and evidence validation
run without model calls. Live execution is a separate, explicitly authorized
operation.

## Install

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev,spreadsheet]"
```

Install a paper environment package only when it is needed:

```bash
python -m pip install -e integrations/spreadsheetbench
python -m pip install -e integrations/alfworld
```

These packages do not download datasets or environment assets.

## Freeze a run before execution

```bash
rethinkskill native-preflight \
  --benchmark searchqa \
  --dataset examples/live_smoke/qa \
  --skill examples/live_smoke/skill.md \
  --out-root runs/smoke \
  --split test \
  --limit 2
```

Preflight hashes external inputs that can drift (dataset files, an optional ID
file, the skill, and task assets). It stores normalized task contracts,
provider configuration, and output scope directly instead of hashing those
derived JSON objects again. It does not create a completed run or establish
that a provider can answer correctly.

`native-run` uses the same inputs and additionally requires
`--authorize-model-calls`. Credentials are supplied through an environment
variable whose name is passed to the CLI; secret values are not serialized.

## Evolve a skill

`native-evolution-preflight` freezes disjoint train and validation selections,
the initial skill, feedback arm, validation gate, target provider, optimizer
provider, and bounded round count. Review that output before replacing the
command with `native-evolve --authorize-model-calls`.

Each round records:

- the current and proposed skill hashes;
- target and optimizer call counts;
- the feedback rows shown to the optimizer;
- candidate validation and gate decisions;
- accepted-skill and best-checkpoint lineage.

## Validate outputs offline

```bash
rethinkskill validate-results runs/<run>/results.jsonl
rethinkskill validate-run runs/<run>
rethinkskill validate-evaluation runs/<evaluation>/manifest.json
```

Validation checks external artifact hashes, schemas, result coverage, call
accounting, lineage, and receipt bindings. Manifests and receipts are strict
JSON but do not carry self-hashes, which would not authenticate a mutable local
file. Validation does not modify outputs, contact a model, or convert a
historical run into a new scientific result.

## Development and release checks

```bash
python -m pytest
python -m pytest \
  experimental/integrations/skillrl/tests \
  experimental/integrations/mce/tests \
  experimental/integrations/webshop/tests
ruff check src tests integrations experimental scripts
python scripts/verify_publication.py
```

CI repeats these checks on Python 3.10, 3.11, and 3.12. Release verification
also builds the main package and five optional packages, compares source bytes
with both wheel and source archives, and installs the wheels in an isolated
environment to validate plugin registration.

## Public repository boundary

The public repository includes implementation, configuration, synthetic test
fixtures, documentation, and release tooling. It excludes formal results, raw
trajectories, model conversations, ledgers, receipts, manuscript sources,
credentials, and local run outputs. Those excluded files remain separate
evidence and are not regenerated by this code release.
